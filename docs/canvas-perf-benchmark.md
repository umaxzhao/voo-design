# Canvas Performance Benchmark

> Generated by `tests/unit/canvas_perf_benchmark.test.js` on 2026-10-23T03:58:34.482Z.
> Re-run with `npx vitest run tests/unit/canvas_perf_benchmark.test.js` or `npm run bench:canvas`.

## Methodology

- Environment: Node v20.19.2, linux/x64, Intel(R) Xeon(R) Processor.
- Runner: Vitest node environment; no browser, DOM, or CanvasKit surface is started for these numbers.
- Synthetic documents: deterministic grid of 80px-spaced nodes built from the production node factories (rect, ellipse, path, image stub).
- Node counts: 1,000 / 5,000 / 20,000 mixed nodes.
- Image-heavy case: 500 image nodes + 4500 rect nodes (5,000 total).
1. Document build: timed construction of all nodes plus the document shell.
2. Spatial index build: `buildSpatialIndex(nodes)` from `src/canvas/editor/viewport_culling.js` (STR bulk load over node visual AABBs).
3. Viewport cull: index is built once, warmed once, then 100 consecutive diagonal pan shifts across the document at zoom 1.0, 1920×1080 screen, 240px world margin; average is `visibleNodeIds` time per shift.
4. Hit-test: 1000 `nodeAtPoint(doc, point, { spatialIndex })` queries at node centres; average is reported in microseconds.
5. Updates: move 50 selected nodes for 60 ticks; one batch `updateNodes({ preview: true })` call per tick versus one sequential `updateNode` call per selected node per tick, through `createEngineNodeOps`.
6. Camera: 1500 `createCameraMatrixTransformer` screen→world→frame→world→screen cycles.
- Memory proxy: `process.memoryUsage().heapUsed` delta between the document build and the end of the warmup + cull pass (after index construction). Forced GC is used when Node exposes it; otherwise this is a noisy proxy, not peak heap.
- Soft gates: index build < 500 ms, cull < 50 ms/cull, hit-test < 25,000 µs/query, camera 1,500 cycles < 500 ms for every case.
- Browser FPS is not measured: Playwright/Puppeteer are not installed in this repository. A system Chrome binary exists, but the benchmark intentionally stays on pure engine modules so CI does not need a browser. This remains a documented gap for paint/FPS work.
- These are single-run wall-clock numbers; treat them as before/after trend indicators, not precise microbenchmarks.
